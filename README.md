# Data Poisoning Study — Iris dataset (MLOps)

This repository contains a small experimental study that explores the effect of data poisoning on a simple Decision Tree classifier trained on the Iris dataset. It demonstrates reproducible ML experiments using DVC (data versioning) and MLflow (experiment tracking), scripts to inject synthetic poisoning (feature noise and label flips), and tests/analysis to detect and summarise poisoning impact.

Author: Ripunjay Kumar

---

## Highlights

- Reproducible data retrieval via DVC (`data/data.csv.dvc`).
- Experiment tracking and model registration using MLflow.
- Two training flows:
	- `train_iris_dt_mlflow.py` — baseline Decision Tree training and MLflow logging.
	- `train_with_poisoning.py` — trains models under different poisoning levels (feature noise and label flips) and logs metrics/artifacts to MLflow.
- An end-to-end orchestration script: `run_poisoning_study.sh` (bash) which pulls data, runs experiments, analyzes results and packages outputs into `poisoning_study_results/`.
- Validation and analysis tests under `tests/` (data validation, model evaluation, robustness checks).

## Repository structure

Relevant files and folders:

- `data/` — DVC-tracked dataset (`data.csv.dvc`).
- `train_iris_dt_mlflow.py` — baseline training + register best model to MLflow.
- `train_with_poisoning.py` — poisoning experiments, metrics and artifact logging to MLflow.
- `run_poisoning_study.sh` — orchestration script (bash) to run the full study and produce `poisoning_study_results/`.
- `src/evaluate_latest_model_mlflow.py` — helper to evaluate the latest registered model from MLflow.
- `tests/` — tests and analysis helpers (data validation, model evaluation, poisoning analysis).
- `poisoning_study_results/` — outputs generated by the study (reports, CSV summaries, confusion matrices).
- `req.txt` and `requirements_poisoning.txt` — Python dependencies used by the project.

## Quick start

Prerequisites

- Python 3.9+ (or compatible)
- DVC (for pulling the dataset)
- MLflow tracking server (optional but recommended to explore runs)

Recommended: create and activate a virtual environment before installing packages.

Windows PowerShell example:

```powershell
python -m venv .venv; .\.venv\Scripts\Activate.ps1
python -m pip install -r req.txt
```

If you plan to run the full poisoning study and analysis, install the extended requirements:

```powershell
python -m pip install -r requirements_poisoning.txt
```

Environment variables

Create a `.env` file or export the following environment variable used by the scripts:

```text
MLFLOW_TRACKING_SERVER=http://localhost:5000
# (adjust to your MLflow server URI)
```

Note: `run_poisoning_study.sh` is a bash script — on Windows you can run it from WSL, Git Bash, or convert the steps to PowerShell. The Python scripts can be executed directly from PowerShell as shown below.

## Typical workflows

1) Pull the DVC-tracked dataset (required before training):

```powershell
dvc pull data/data.csv.dvc
```

2) Run baseline training and register a model in MLflow:

```powershell
python train_iris_dt_mlflow.py
```

3) Run the poisoning experiments (multiple poisoning levels will be tried and logged):

```powershell
python train_with_poisoning.py
```

4) Or run the orchestration script (bash) that runs training, analysis, tests and collects results:

```bash
./run_poisoning_study.sh
```

5) Evaluate the latest registered model from MLflow:

```powershell
python src/evaluate_latest_model_mlflow.py
```

## Results and outputs

Artifacts, summaries and visualizations produced by the study are stored under `poisoning_study_results/` when using the orchestration script. Typical outputs:

- `poisoning_summary.csv` — tabular summary of all runs and metrics.
- `confusion_matrix_*.png` — confusion matrices for each poisoning level/run.
- `cml_report_poisoning.md` and `metrics_poisoning.json` — CI/CD-friendly summary and metrics.
- `data_validation_report.json`, `robustness_metrics.json` — validation and robustness checks.

You can also inspect all runs and artifacts interactively via the MLflow UI at the `MLFLOW_TRACKING_SERVER` URL.

## Running tests

This repository includes pytest-based checks for data quality and model evaluation. To run tests:

```powershell
pytest -q
```

Note: Some tests may reach out to cloud storage or expect a configured MLflow server. If you do not have those services available, run the subset of tests that operate purely on local files or run them after setting up the tracking server and credentials.

## Notes on reproducibility

- DVC is used to track the dataset. The code calls `dvc pull` to fetch the exact version referenced by `data/data.csv.dvc`.
- MLflow tags and run metadata include the current Git commit (see training scripts), which helps map runs back to code.
